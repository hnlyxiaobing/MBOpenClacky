## 问题 3：剩余风险

### 原问题描述

- cmd 的 C 编译失败是预存的 `unistd.h` 问题（Windows MSVC）
- 内存会话存储 — 服务重启后会话丢失
- 随机数使用 SHA256 确定性种子

### 当前状态：✅ 设计层面已处理

| 风险项 | 当前处理方式 | 评估 |
|--------|-------------|------|
| `unistd.h` / MSVC | `lib/client/http_thread.c` 中 `#ifdef _WIN32` 使用 `<windows.h>`，`#else` 使用 `<unistd.h>` | ✅ 已正确处理 |
| 内存会话存储 | 设计如此，服务重启后会话丢失符合"不持久化"的设计意图 | ✅ 无需改动 |
| 随机数确定性种子 | 仅在 `MBOPENCLACKY_NO_OPENSSL` 时使用弱加密存根，正常构建使用 OpenSSL `RAND_bytes`；CI 有 `check-crypto-build.sh` 守卫 | ✅ 已有安全机制 |

`brand_stubs.c` 中的弱加密存根：
- 有 `#ifdef MBOPENCLACKY_NO_OPENSSL` 条件编译
- 有 `#error` 硬守卫（需同时定义 `MBOPENCLACKY_INSECURE_DEBUG_BUILD`）
- CI 中 `check-crypto-build.sh` 拒绝 release 构建包含弱加密
