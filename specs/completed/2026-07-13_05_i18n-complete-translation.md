## 问题描述

当前前端 i18n 翻译已迁移至 MoonBit 实现，翻译 key 数量从 Spec 初始的 ~394 keys 增加到 733 keys（英文）和 735 keys（中文）。需要进一步补齐缺失的翻译 key，确保覆盖所有 Web 面板功能。

**前提条件**：原项目 `i18n.js` 源文件不在当前仓库中，需通过原项目仓库获取或基于当前代码分析缺失项。

## 现状分析

- **i18n 框架已迁移**：从原 Spec 设想的 `web/js/i18n.js`（2,784 行）架构完全迁移至 `web/mb` 目录下的 MoonBit 实现。
- **当前文件结构**：
  - `web/mb/main/i18n_helpers.mbt`（102 行）：定义 `t()`、`t1()`、`i18n_lookup()`、`i18n_substitute()`、`locale_change_cmd()` 等核心函数
  - `web/mb/main/i18n_dict_en.mbt`（738 行）：英文翻译字典，733 个 key
  - `web/mb/main/i18n_dict_zh.mbt`（740 行）：中文翻译字典，735 个 key
- **翻译机制**：
  - `t(key)`：无参数翻译，调用 `i18n_lookup(key)`
  - `t1(key, name, value)`：单参数翻译，支持 `{{param}}` 占位符替换
  - `i18n_get_locale()`：从 localStorage 读取当前语言设置（默认 "en"）
  - `locale_change_cmd()`：监听 `i18n:locale-changed` 事件，触发视图重新渲染
- **后端 i18n**：`lib/i18n`（164 行）已基本对齐原项目 `locales/`（114 行）。
- **翻译 key 格式**：点分隔字符串（如 `"sessions.title"` / `"settings.model"`），存储在平铺字典中。
- **当前缺失翻译**：在 Web 面板中显示为原始 key（`t()` 在找不到 key 时返回 key 本身）。

## 决策

1. **基于当前 733 keys 基线进行补齐**：分析代码中使用的翻译 key，识别缺失项。
2. **中英文同步补齐**：每个 key 同时提供 en 和 zh 翻译，不产生新的不对称。
3. **翻译优先级按面板使用频率**：sessions > settings > extensions > onboard > 其他。
4. **翻译值保持一致性**：确保新增翻译与现有翻译风格一致。

## 改动范围

- **涉及文件**：`web/mb/main/i18n_dict_en.mbt`、`web/mb/main/i18n_dict_zh.mbt`
- **不涉及**：后端 `lib/i18n`（已完成）、`i18n_helpers.mbt`（框架已稳定）、TUI i18n

## 实施计划（任务包切分）

1. **代码分析**：扫描 `web/mb/main/` 目录下所有 `.mbt` 文件，提取使用的翻译 key。
2. **差异识别**：对比当前字典与代码中使用的 key，识别缺失项。
3. **sessions 组补齐**：会话面板相关翻译。
4. **settings 组补齐**：设置面板相关翻译。
5. **extensions 组补齐**：扩展市场/发布/安装相关翻译。
6. **onboard 组补齐**：引导流程相关翻译。
7. **其他补齐**：剩余面板（brand/billing/channels/mcp/trash 等）翻译。
8. **验证**：Web 面板手动检查，确认无原始 key 暴露。
