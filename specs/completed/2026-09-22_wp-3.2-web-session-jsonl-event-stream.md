## 问题描述 [必填]

会话事件日志（append-only JSONL）目前只在 CLI 路径产出：`SessionLogProducer` 定义于 `cmd/inspect.mbt:28`，由 `cmd/main.mbt:991/1024/1157` 在 `--message` 与 TUI 运行路径上 attach/flush。`lib/web` 对它零引用——Web 会话运行后只落整份 `.json` 快照，无逐事件 JSONL。结果是三端可观测性不一致：CLI/TUI 会话可用 `cmd inspect` 离线回放（含压缩投影），Web 会话不可。

`docs/known-gaps.md` 已将该缺口如实登记为 `open`（决策 D3 曾划为范围外）——**这是已披露的能力缺口，不是可信度问题**。执行计划 WP-3.2 的背景项明确：若追求三端一致，在广播层加持久化旁路，复用值类型的 `SessionLogProducer`。

### 详细分析

**为什么 producer 下沉而不是在 lib/web 复制一份**：写原语（append/summary/read）与 DoD 不变量全部在 `lib/agent/session_log.mbt`；复制 producer 会让"压缩→Summary 追加"这条核心不变量出现两份实现。下沉后 `cmd` 的 `attach_session_log`/`flush_session_log` 与 `cmd/session_log_producer_wbtest.mbt` 语义不变（公共 API 面不动），`lib/web` 直接消费同一实现。

**为什么喂事件不挑拣**：Web hook 出于 UI 需求会抑制部分广播（如中断后的矛盾 complete）。但会话日志的契约是"记录引擎实际发出的事件"（与 CLI/TUI 一致），不是"记录 UI 看到的事件"。抑制是广播层的呈现决策；日志层旁路发生在抑制之前，语义与 CLI 完全一致。

**为什么 flush 在 save_session 同位**：save_session 的四个调用点是 run 生命周期的收尾（成功/错误/中断全覆盖），此刻 producer 缓冲完整、且失败也不会丢——错误路径同样要落盘（用户输入不能丢，与 save_session 的注释动机一致）。flush 本身遵循"日志失败不影响 run"纪律：目录获取失败即静默返回，缓冲留给下次运行继续追加（seq 从文件重读，不丢不撞）。

**为什么 per-session producer 放 `WsSessionState`**：Web 服务多会话并发；CLI 的进程级单例在这里是错的。`ws_states` 按 session_id 存活，producer 作为其值字段天然隔离；`state.running` 门保证同一会话的 run 串行，无并发追加同一文件的风险（跨进程由 advisory lock + seq 重读兜底）。

## 决策 [必填 - 含为什么]

1. **决策 1（producer 下沉 `lib/agent/session_log.mbt`）**：`SessionLogProducer`/`SessionLogSegment` 及 `new`/`on_hook_event`/`buffered`/`flush`/段事件追加助手整体迁为 `pub`，逻辑逐字保留；`cmd/inspect.mbt` 删除定义、保留 `attach_session_log`/`flush_session_log` 薄包装（签名与语义不变）。
   - **为什么**：lib/web 依赖方向约束 + 单一实现保证压缩不变量只有一份。
2. **决策 2（Web per-session producer 挂 `WsSessionState`）**：新增 `producer : @agent.SessionLogProducer` 字段；`register_ws_hooks` 的 hook 闭包在广播 match **之前**统一 `producer.on_hook_event(evt)`。
   - **为什么**：多会话并发正确性；"日志记录引擎所见"与广播抑制解耦。
3. **决策 3（flush 挂四个 run 退出路径的 save_session 同位，`buffered()==0` 短路）**：新建 web 内 `flush_ws_session_log(state, session_id, created_at, sessions_dir?)` 助手；`sessions_dir` 缺省 `ensure_sessions_dir()`（失败静默返回，绝不抛出）。
   - **为什么**：全覆盖（成功/错误/中断/异步/同步回退）；显式目录参数让 wbtest 用 scratch 目录，不动用户真实 home。
4. **决策 4（不新建空文件）**：`buffered()==0` 时不调 flush——沿用 CLI `flush_session_log` 的既有守卫，避免无事件会话（如纯 interrupt）产生空 `.jsonl`。
   - **为什么**：空文件对 `cmd inspect` 是噪声；CLI 已确立该语义。
5. **决策 5（不动广播路径与协议层）**：`format_hook_event`、Hub、ws 帧 wire 格式零改动；JSONL 行格式沿用 `lib/agent/session_log.mbt` 既有 schema（version 头 + seq/unix_ms 信封）。
   - **为什么**：DoD 只要求持久化旁路；wire 格式是另一契约（ADR-0001 面），不越界。
6. **决策 6（会话删除不联动清理 `.jsonl`）**：显式范围外。删除会话已删 `.json`；`.jsonl` 若存在则留存（append-only 哲学：日志只增）。
   - **为什么**：与 CLI 行为一致（CLI 删除同样不清 `.jsonl`）；联动清理属独立决策。
