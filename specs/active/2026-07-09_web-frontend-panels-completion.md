## 核心目标

将 Web 前端从 ~9,191 行（原项目 37,711 行的 24%）向功能完整推进。已完成 8 个管理面板（MCP/IM/Cron/Backup/Billing/Browser/Trash/Git）。本轮补齐原项目 SPA 中仍缺失的面板与富组件。

## 关键能力

- **扩展市场面板**：浏览/搜索/安装/启用/禁用/卸载扩展（接 P1-1 Marketplace API）。
- **创作者工作室面板**：scaffold/编辑/打包/发布扩展（接 P1-1 Scaffold/Publish）。
- **媒体生成面板**：图像/视频/音频/TTS 生成 UI（后端 `lib/media` 已就绪）。
- **任务面板**：Agent todo/任务列表展示与操作。
- **会议面板**：接 P1-3。
- **富组件**：CodeMirror 代码编辑器、KaTeX 数学渲染、QRCode、日期选择器、富 UI 对话框。
- **前端 i18n**：与 P1-7 协同保持键值一致。

## 明确不做

- 不做移动端深度 polish（原因：P2 范围）。
- 不重写已完成 8 面板（原因：仅增量）。
- 不引入未评估的重量级框架（原因：保持轻量 SPA 风格）。
- 不做后端 API（原因：由 P0-2 / P1-5 / P1-1 / P1-3 提供）。

## 关键决策（含为什么）

1. **按面板切最小混沌单元**：每个面板 = 1 个任务包，对齐 harness 方法论的 Web 面板切分建议。
2. **富组件优先轻量库**：CodeMirror 6 / KaTeX / qrcode.js，单文件引入，避免构建链复杂化。
3. **前端与后端契约以 P0-2 对照表为准**：避免再次出现 404。
4. **顺序**：先做无后端依赖的面板（任务、富组件），再做依赖 P1-1/P1-3 的市场/会议面板。
