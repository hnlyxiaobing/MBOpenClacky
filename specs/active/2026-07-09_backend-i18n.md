## 核心目标

原项目有 `lib/clacky/locales/en.rb`、`locales/zh.rb` 提供后端国际化字符串（错误提示、系统消息等）。MBOpenClacky 前端已有 `web/js/i18n.js`，但后端无对应 i18n 能力。本 spec 决定后端 i18n 的实现策略并落地最小可用版本。

## 关键能力

- 后端可按语言返回本地化字符串（en/zh 起步）。
- 与前端 i18n 键值协调，避免两套翻译分散。
- 语言来源：配置项 + 运行时切换（Web/IM 渠道）。

## 明确不做

- 不做完整多语言覆盖全量字符串（原因：先建机制 + 覆盖关键路径）。
- 不引入 i18n 框架依赖（原因：MoonBit 无成熟 i18n 库，自建轻量键值表即可）。
- 不做 TUI 的 i18n（原因：TUI 字符串较少，后续按需）。

## 关键决策（含为什么）

1. **统一到前端 i18n 键值体系**：避免后端/前端两套翻译，后端复用相同 key 命名约定，翻译表放在共享资源。
2. **轻量键值表**：`lib/utils` 或新 `lib/i18n` 维护 `Map[String, Map[String, String]]`，按 locale 查找。
3. **关键路径优先**：错误提示、IM 渠道消息、Web API 错误响应先覆盖。
4. **语言来源链路**：渠道配置 > 会话设置 > 全局默认。

## 验收维度

- [ ] 后端 i18n 机制可用（按 locale 返回字符串）
- [ ] en/zh 覆盖关键错误/消息路径
- [ ] 与前端 i18n 键值约定一致
- [ ] `moon check` 0 errors
