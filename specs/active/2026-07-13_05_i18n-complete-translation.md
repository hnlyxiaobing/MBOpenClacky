## 问题描述

差距分析显示前端 i18n 翻译覆盖率约 41%（按行数 872/2117 计算）。原项目 `i18n.js`（2,117 行，含 en + zh 双语），当前 `web/js/i18n/en.js`（436 行，~394 keys）+ `zh.js`（436 行，~394 keys）合计仅 872 行。主要缺失领域：extension 相关（publish/install/marketplace）、session 相关、settings 相关、onboard 引导流程。

**前提条件**：需获取原项目 `i18n.js` 源文件作为翻译基准。当前仓库中不包含原项目源码，需通过差距分析文档 §附录 C 或原项目仓库获取。

## 现状分析

- `web/js/i18n.js`（2,784 行）：i18n 框架，支持 `t(key, params)` 翻译 + `setLocale(locale)` 切换 + `translateDOM()` DOM 批量翻译（`data-i18n` / `data-i18n-placeholder` / `data-i18n-title` 属性）。翻译 key 和值已整合到此文件中。
- 后端 `lib/i18n`（164 行）已基本对齐原项目 `locales/`（114 行）。
- 翻译 key 格式为点分隔字符串（如 `"sessions.title"` / `"settings.model"`），存储在平铺字典中。
- 当前缺失翻译在 Web 面板中显示为原始 key（`I18n.t()` 在找不到 key 时返回 key 本身）。

## 决策

1. **从原项目 `i18n.js` 提取所有翻译 key 作为基准**：生成完整 key 清单，逐条补齐。
2. **中英文同步补齐**：每个 key 同时提供 en 和 zh 翻译，不产生新的不对称。
3. **翻译优先级按面板使用频率**：sessions > settings > extensions > onboard > 其他。
4. **翻译值保留原项目措辞**：直接移植原项目 i18n.js 的翻译值，保持一致性。

## 改动范围

- **涉及文件**：`web/js/i18n/en.js`、`web/js/i18n/zh.js`
- **不涉及**：后端 `lib/i18n`（已完成）、TUI i18n、其他 JS 文件逻辑

## 实施计划（任务包切分）

1. **提取完整 key 清单**：从原项目 `i18n.js` 解析出所有翻译 key 和 en/zh 值。
2. **sessions 组补齐**：会话面板相关翻译（~200 keys）。
3. **settings 组补齐**：设置面板相关翻译（~150 keys）。
4. **extensions 组补齐**：扩展市场/发布/安装相关翻译（~200 keys）。
5. **onboard 组补齐**：引导流程相关翻译（~100 keys）。
6. **其他补齐**：剩余面板（brand/billing/channels/mcp/trash 等）翻译（~400 keys）。
7. **验证**：Web 面板手动检查，确认无原始 key 暴露。

## 验收标准

- [ ] i18n 翻译 key 数量达到原项目的 95% 以上（当前 ~394 keys，目标 ≥ 原项目 key 数 × 0.95）
- [ ] `en.js` 和 `zh.js` 的 key 集合完全一致（无 en 有而 zh 无的 key，反之亦然）
- [ ] Web 面板中不再出现原始翻译 key（`I18n.t()` 不返回 key 本身）
- [ ] 中英文切换后所有面板文案正确显示
- [ ] `translateDOM()` 正确翻译所有 `data-i18n` 属性元素
